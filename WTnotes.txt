--> A cross-cutting concern is a concern which can affect the entire application.

Why AOP?
it provides a pluggable way to dynamically add the additional concern before after and around the actual logic.

Core concepts of AOP:
1. Advice: method that tells when to execute
2. Pointcut: Where will this advice run, before, after func call or after getting error
3. Target Object: 
4. Aspect: What to implement
5. Proxy: means behalf => AOP works on behalf of some module etc.
6. Weaving: Different modules get connected together via AOP.
7. Join Point: Where you want to get the execution.


Bean Scopes:
--> When the spring framework creates a bean, it associates a scope with the bean. A scope defines the runtime context within which the bean instance is available.
--> In spring, a bean can be associated with the following scopes:
    => Singleton;
    => Prototype;
    => Request;
    => Session;
    => WebSocket;
    => Application.

@Scope("singleton")

by default => scope is singleton => example in case of aadhar card, pan card

Singleton
it is default one.
single bean object instance per spring IoC container.

Prototype 
Opposite to singleton, it produces a new instance each and every time a bean is requested.
=> example, number of products => number of instances 

Request 
A single instance will be created and available during complete lifecycle of an HTTP request.
-> only works in browser
-> can be used as a model on web and not be used outside the web.
-> only valid in web-aware Spring ApplicationContext.

Session
A single instance will be created and available during complete lifecycle of an HTTP session.
-> only valid in web-aware Spring ApplicationContext.
@Scope("session") 
@SessionScope

Application 
A single instance will be created and available during complete lifecycle of ServletContext.
-> only valid in web-aware Spring ApplicationContext.
@Scope("application")
@ApplicationScope

WebSocket
A single instance will be created and available during complete lifecycle of WebSocket.
-> only valid in web-aware Spring ApplicationContext.
@Scope("websocket")

What is design pattern?
=> A design pattern is a well-proved solution for solving the specific problem/task.
Sureity but no guarantee

*Advantage of Design Pattern*
- reusable in multiple projects
- provide the solutions that help to define the system architecture.
- capture the s/w engineering experiences.
- provide transparency to the design of an application
- well proved, testified solutions since they have been bult upon the knowledge and experience of expert s/w developers
- design pattern do not guarantee an absolute solution to a problem. They provide clarity to the system architect and possibility of


categories of Design pattern:
- Creational
	factory, abstract factory, prototype, singleton
- Structural
	adapter(MVVM), bridge, composite, decorator, facade, flyweight, proxy
- Behavioral
	Command, iterator, interpreter, mediator, memento, observer, state, strategy, template,



Factory design pattern
we define an interface or abstract class for creating an object but let the subclasses decide which class to instantiate.
in other words, subclasses are responsible to create the instance of the class.
factory method pattern is also known as Virtual constructor
Advantage => allows subclasses to choose the type of the object to be instantiated.
=> loosely coupled is implemented 
=> runtime polymorphism is implemented (upcasting).
